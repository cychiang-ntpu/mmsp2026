## 作業 1：訊息加上暱稱與時間戳記　★☆☆

**目標**：泡泡上顯示「誰、幾點幾分」說的，例如 `Amy 14:05` 哈囉！

**提示**：
- 設計一個簡單的文字格式，例如送出前把訊息組成 `名字|14:05|哈囉`，
  收到時再用 `|` 拆開。組字串用 `snprintf`，拆字串可用 `strchr` 或 `strtok`。
- 取得現在時間：`#include <time.h>`，用 `time()` + `localtime()` + `strftime()`。
- 暱稱可以從命令列參數多收一個，或程式開頭用 `fgets` 問一次。

**要看的程式段落**：主迴圈送出訊息處（第 6 區段 main 的「等使用者打字 → 送出」），
以及接收執行緒 `recv_thread`（第 4 區段）收到訊息後存入紀錄的地方。

**完成標準**：雙方畫面上每個泡泡都看得到暱稱與時間；`/quit` 等既有功能不受影響。

## 作業 2：修正中文（全形字）的泡泡寬度　★★☆

**目標**：目前泡泡寬度是用 `strlen` 之類的位元組長度算的，
中文一個字佔 3 個位元組（UTF-8）但畫面上佔 2 格寬，所以泡泡框會歪掉。修好它。

**提示**：
- 先實驗：傳一句中文，觀察泡泡框歪掉的樣子，理解「位元組數 ≠ 顯示寬度」。
- 寫一個函式 `int display_width(const char *s)`：逐位元組掃過字串，
  UTF-8 中開頭位元組 >= 0x80 的多位元組字元（中文）算寬度 2，ASCII 算 1。
- 把畫泡泡時所有用長度的地方換成這個函式。

**要看的程式段落**：第 3 區段的 `draw_bubble()`——泡泡框線與寬度都在這裡算。

**完成標準**：中英文混雜的訊息，泡泡框線仍然整齊對正。

## 作業 3：TCP 黏包／斷包處理（長度前綴）　★★★

**目標**：TCP 是「位元組串流」，不保證你 `send` 一次對方就剛好 `recv` 到一次。
連續快速送兩則訊息可能黏成一包，長訊息也可能被拆成兩包。
加上「長度前綴」讓訊息永遠正確切割。

**提示**：
- 協定改成：先送 4 個位元組的長度（可用 `uint32_t` + `htonl` 轉網路位元組序），
  再送訊息本體。
- 收的那端寫一個 `recv_all(sock, buf, n)`：用迴圈反覆 `recv` 直到湊滿 n 個位元組。
  先 `recv_all` 4 位元組拿到長度（`ntohl` 轉回來），再 `recv_all` 該長度的本體。
- 想觀察黏包：寫個迴圈連續 `send` 十次短訊息，看舊版程式收到什麼。

**要看的程式段落**：主迴圈的 `send()`（第 6 區段）與 `recv_thread` 的 `recv()`（第 4 區段）。
UDP 模式不用改——UDP 本來就是一包一包的，想想為什麼？

**完成標準**：連續快速送出多則與超長訊息，對方每則都完整分開顯示。

## 作業 4：一對多聊天室　★★★

**目標**：現在是一對一。把 server 改成能同時服務多個 client，
任何人說話，其他所有人都看得到。

**提示**：
- 兩條路擇一：(a) 每 `accept` 一個 client 就開一條執行緒服務它；
  (b) 用 `select()` 在單一迴圈裡同時監聽所有 socket。新手建議先走 (a)。
- server 要維護一個「目前所有 client socket」的陣列（記得上鎖，
  程式裡已經有現成的 mutex 可以參考用法）。
- 收到某人的訊息後，迴圈轉發給陣列中**其他**每一個 client。
- 搭配作業 1 的暱稱格式，才知道是誰說的。

**要看的程式段落**：第 5 區段的 `tcp_server()`（目前只 `accept` 一次），
與第 4 區段接收執行緒的建立方式（模仿它多開幾條）。

**完成標準**：三個以上 client 同時連上，任一人發話全員都收到；
一人離線不影響其他人。

## 作業 5：用 UDP 傳聲音，聽聽掉封包　★★★

**目標**：把錄音檔的取樣資料透過 UDP 一包一包送到對方，存下來播放，
聽聽看掉封包對聲音的影響——這就是為什麼視訊通話用 UDP 也偶爾會破音！

**提示**：
- 準備一個 WAV 檔（未壓縮 PCM 最單純；WAV 前 44 個位元組是檔頭，之後全是取樣資料）。
- 傳送端：`fopen`+`fread` 每次讀固定大小（例如 1024 位元組）就 `sendto` 一包，
  包與包之間可 `Sleep`/`usleep` 幾毫秒模擬串流。
- 接收端：`recvfrom` 收到就 `fwrite` 進新檔案，補上 WAV 檔頭後即可播放比較。
- 進階：在每包開頭加序號，接收端偵測哪些包不見了、統計掉包率。

**要看的程式段落**：第 5 區段的 `udp_setup()` 與收發用的 `sendto`/`recvfrom`。
這題建議另外寫兩個小程式（sender.c / receiver.c），不必硬塞進 chat.c。

**完成標準**：對方存下的檔案能播放；能說出（最好能量測）掉封包時聲音發生什麼事。
