# VSCode 除錯教學：一行一行看你的 C 程式怎麼跑

寫程式一定會遇到「結果不對，但不知道錯在哪」的時候。
與其到處加 `printf`，不如學會用 **debugger（除錯器）**：
它可以讓程式**暫停在你指定的那一行**，然後一行一行往下執行，
隨時看每個變數現在的值是多少。

> 開始前請先完成《VSCode C 語言開發環境設定教學》：
> 你需要已安裝好 VSCode、GCC（MSYS2）以及 Microsoft 的 C/C++ 擴充套件。

---

## 三個核心觀念

| 名詞 | 意思 |
|------|------|
| **中斷點 (Breakpoint)** | 你在某一行做的記號，程式跑到這一行會**暫停** |
| **逐行執行 (Step)** | 暫停後，按一個鍵讓程式**只執行一行**，然後再度暫停 |
| **監看變數 (Watch)** | 程式暫停時，查看任何變數目前的值 |

---

## 步驟 1：準備一個練習用的程式

建立一個新資料夾（例如 `debug_practice`），用 VSCode 開啟它，
新增檔案 `sum.c`，貼上以下程式（它計算 1 加到 5，故意寫得囉嗦一點方便觀察）：

```c
#include <stdio.h>

int add(int a, int b)
{
    int result = a + b;
    return result;
}

int main(void)
{
    int total = 0;

    for (int i = 1; i <= 5; i++) {
        total = add(total, i);
        printf("i = %d, total = %d\n", i, total);
    }

    printf("1 加到 5 = %d\n", total);
    return 0;
}
```

記得存檔（`Ctrl+S`）。

---

## 步驟 2：設定中斷點

1. 把滑鼠移到 `int total = 0;` 那一行的**行號左邊**。
2. 會出現一個淡紅色的小圓點，**點一下**，變成實心紅點。
   這就是中斷點——程式執行到這一行會停下來。
3. 再點一次紅點可以取消。

---

## 步驟 3：啟動除錯

1. 確定目前開啟的分頁是 `sum.c`。
2. 按 **F5**（或上方選單 `Run > Start Debugging`）。
3. 第一次會跳出選單問你用哪個編譯器：
   - 選 **C/C++: gcc.exe 建置及偵錯使用中檔案**
     （路徑通常是 `C:\msys64\ucrt64\bin\gcc.exe`）。
   - VSCode 會自動幫你產生設定檔（`.vscode` 資料夾），以後按 F5 就不會再問。
4. 程式開始執行，然後**停在你的紅點那一行**——
   該行會反黃並出現一個黃色箭頭，表示「下一行要執行的就是這行」。

> 如果按 F5 出現錯誤，最常見原因是 gcc 的 PATH 沒設定好，
> 先回到環境設定教學確認終端機打 `gcc --version` 有反應。

---

## 步驟 4：認識除錯畫面

程式暫停時，注意畫面上的兩個地方：

**左側面板：**
- **VARIABLES（變數）**：目前所有變數的值。現在 `total` 可能是亂數，
  因為 `int total = 0;` 這行**還沒執行**（黃色箭頭指著的行是「即將執行」）。
- **WATCH（監看）**：按 `+` 可以自己輸入想追蹤的算式，例如 `total + i`。
- **CALL STACK（呼叫堆疊）**：現在程式執行到哪個函式裡。

**上方浮動工具列（除錯的遙控器）：**

| 按鈕 | 快速鍵 | 功能 |
|------|--------|------|
| ▶ Continue | `F5` | 繼續執行，直到碰到下一個中斷點 |
| ⤵ Step Over | `F10` | **執行一行**（遇到函式呼叫直接算完，不進去） |
| ⬇ Step Into | `F11` | 執行一行，遇到函式呼叫就**走進函式裡面** |
| ⬆ Step Out | `Shift+F11` | 把目前這個函式跑完，回到呼叫它的地方 |
| ⏹ Stop | `Shift+F5` | 強制結束除錯 |

---

## 步驟 5：實際逐行走一遍

跟著做，體會逐行除錯的感覺：

1. 程式停在 `int total = 0;`。按一次 **F10**。
   → 看左側 VARIABLES：`total` 變成 `0` 了。
2. 繼續按 **F10**，進入 for 迴圈，`i` 出現且等於 `1`。
3. 黃色箭頭停在 `total = add(total, i);` 時，改按 **F11**（Step Into）。
   → 畫面跳進 `add` 函式！VARIABLES 顯示 `a = 0`、`b = 1`。
4. 按 **F10** 執行 `int result = a + b;`，看到 `result = 1`。
5. 按 **Shift+F11**（Step Out）跳出函式，回到 main。
6. 把滑鼠**移到程式碼中的變數名稱上**（例如 `total`），
   會直接浮出它現在的值——這是最常用的看值方式。
7. 按 **F5**（Continue），程式一口氣跑完這圈迴圈，
   又停回中斷點嗎？不會——中斷點在迴圈外，所以直接跑到結束。
   想每圈都停，就把中斷點設在**迴圈裡面**那行再試一次。

---

## 步驟 6：用 debugger 抓一隻真正的 bug

把 for 迴圈那行故意改錯：

```c
    for (int i = 1; i < 5; i++) {   /* <= 改成 < */
```

存檔後重新按 F5。程式輸出 `1 加到 5 = 10`，答案錯了（應該是 15）！

抓法：在 `total = add(total, i);` 設中斷點，按 F5 啟動，
每次停下來就看 `i` 的值，再按 F5 跳到下一圈。
你會發現 `i` 走到 `4` 之後就不再停了——`i = 5` 那圈根本沒執行，
問題就出在 `i < 5` 應該是 `i <= 5`。

這就是 debugger 的威力：**不用猜，直接看程式真實的執行過程。**

## 常見問題（FAQ）

**Q1：按 F5 後閃一下黑視窗就沒了？**
你可能沒設中斷點，程式一口氣跑完就結束了。先設中斷點再按 F5。

**Q2：紅點變成灰色空心圓？**
表示 debugger 對不上這行程式。通常是改了程式**忘記存檔**，
或編譯時沒有除錯資訊——用 VSCode 的 F5 流程會自動加上 `-g` 參數，
若你自己下指令編譯，記得加：`gcc -g sum.c -o sum`。

**Q3：VARIABLES 面板變數的值是奇怪的大數字？**
那個變數還沒被指定初始值（黃色箭頭還沒走過它的那一行），
記憶體裡是殘留的垃圾值。這也提醒你：**變數要記得初始化！**

**Q4：F10 和 F11 到底差在哪？**
都執行「一行」。差別在遇到函式呼叫時：F10 把整個函式當一步跳過，
F11 會走進函式裡面一行行看。不確定就先用 F10，想深入某個函式再用 F11。

## 下一步

- 打開之前的 `hello.c` 或聊天程式 `chat.c`，設中斷點走走看。
- 學「條件中斷點」：在紅點上**按右鍵 > Edit Breakpoint**，
  輸入 `i == 3`，程式只會在 `i` 等於 3 時停下——迴圈跑很多次時超好用。
- 之後寫作業卡關時，第一反應不要再是狂加 printf，
  而是：**設中斷點，F5，逐行看**。
